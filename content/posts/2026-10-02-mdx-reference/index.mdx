Este é o segundo post da série **Manual do Blog** e cobre tudo o que você pode usar **dentro do texto** de um post: Markdown, blocos de código e componentes MDX. Mantenha-o aberto como guia enquanto escreve.

Os recursos que ficam _em volta_ do texto (metadados, status, capa, séries e autores) estão no post anterior, [Como o blog funciona](/blog/como-o-blog-funciona). Se ainda não criou nenhum post, comece por ele.

## Markdown nativo

O Markdown padrão funciona normalmente. Todos os elementos abaixo não precisam de componentes extras.

<Callout variant='tip' title='Chaves e sinais de menor'>
  No MDX, chaves e sinais de menor no texto corrido são lidos como JSX. Para
  mostrá-los, coloque-os em `código inline` ou escape-os com uma barra
  invertida.
</Callout>

### Tipografia

**Negrito**, _itálico_, ~~tachado~~ e `código inline` funcionam nativamente. O tachado exige dois til de cada lado: um só não funciona.

> Blockquote para destacar citações ou trechos importantes de outras fontes.

### Âncoras em headings

O título do post é o `h1` da página, então comece os títulos do texto em `##`.

Todos os headings (`##`, `###`, etc.) recebem automaticamente um `id` gerado a partir do texto (via `rehype-slug`). Os de nível 2 a 4 (`##` a `####`) ganham também um link âncora `#`, clicável ao passar o mouse (via `rehype-autolink-headings`).

O `id` é o texto em minúsculas, com hífens no lugar dos espaços e mantendo os acentos. Use para linkar diretamente para uma seção:

```md
[Ir para seção "# Âncoras em headings"](#âncoras-em-headings)
```

[Ir para seção "# Âncoras em headings"](#âncoras-em-headings)

### Índice do post

Os títulos `##` e `###` formam o índice **Neste post**, montado automaticamente quando o post tem mais de um deles. A partir do breakpoint `xl` (1280 px) ele fica fixo ao lado do texto e acompanha a leitura; em telas menores vira uma lista recolhível antes do conteúdo. Títulos `####` ganham âncora, mas não entram no índice.

### Links

Links internos e externos são tratados automaticamente pelo componente `Link` da pasta `components/mdx/link.tsx`:

- `[texto](/rota)` → link interno com Next.js, sem recarregar a página
- `[texto](https://...)` ou `[texto](http://...)` → abre em nova aba (`target="_blank"` e `rel="noopener noreferrer"`) e mostra um ícone de link externo, com o aviso "(abre em nova aba)" para leitores de tela
- `[texto](#secao)` e `mailto:` → `<a>` simples, sem tratamento especial

O `remark-gfm` também transforma endereços soltos no texto em links:

- `https://exemplo.com` → link externo
- `www.exemplo.com` → link externo, mas com o prefixo `http://` (e não `https://`); prefira escrever a URL completa
- `contato@exemplo.com` → link de e-mail (`mailto:`)

Exemplos:

- [Link interno](/blog/mdx-reference)
- [Link externo](https://google.com)
- https://google.com
- www.google.com
- contato@exemplo.com

### Listas

Lista não ordenada:

- Item simples
- Item com `código inline`
- Item com **negrito** ou _itálico_

Lista ordenada:

1. Primeiro passo
2. Segundo passo
3. Terceiro passo

Lista de tarefas (via remark-gfm):

- [x] Tarefa concluída
- [ ] Tarefa pendente

## Código

O `rehype-pretty-code` processa os blocos de código com syntax highlight automático, usando o tema One Dark Pro. O componente `CodeBlock` adiciona o botão de copiar, que ignora as linhas marcadas como removidas (`// [!code --]`, descrito adiante). Blocos sem linguagem são exibidos como texto simples, e o código inline não recebe highlight.

Bloco simples:

```ts
function greet(name: string): string {
  return `Hello, ${name}!`;
}
```

Com `title` e `caption`:

```ts title="utils/greet.ts" caption="Função utilitária de saudação."
function greet(name: string): string {
  return `Hello, ${name}!`;
}
```

Com `showLineNumbers`:

```tsx title="components/button.tsx" showLineNumbers
interface ButtonProps extends React.ComponentProps<'button'> {
  variant?: 'default' | 'outline' | 'ghost';
}

export function Button({
  variant = 'default',
  className,
  ...props
}: ButtonProps) {
  return (
    <button className={cn(buttonVariants({ variant }), className)} {...props} />
  );
}
```

Linhas marcadas com um comentário especial no fim ganham tratamento próprio. Diff, para mostrar o que sai e o que entra:

```ts
const old = 1; // [!code --]
const novo = 2; // [!code ++]
```

Highlight, para destacar uma linha:

```ts
const importante = 3; // [!code highlight]
const naoImportante = 4;
const outroImportante = 5;
```

Focus, para dar foco a uma linha:

```ts
console.log('focus');
const importante = 3; // [!code focus]
console.log('focus');
```

| Notação                | Efeito           |
| ---------------------- | ---------------- |
| `// [!code ++]`        | Linha adicionada |
| `// [!code --]`        | Linha removida   |
| `// [!code highlight]` | Linha destacada  |
| `// [!code focus]`     | Linha em foco    |

Para destacar sem mexer no código, use a meta da cerca, logo depois da linguagem, na linha que abre o bloco:

| Meta da cerca | Efeito                                           |
| ------------- | ------------------------------------------------ |
| `{2,4-5}`     | Destaca a linha 2 e as linhas de 4 a 5           |
| `/texto/`     | Destaca o trecho `texto` em todas as ocorrências |

Linhas destacadas com `{2}`:

```ts {2}
const primeira = 1;
const segunda = 2;
const terceira = 3;
```

Trecho destacado com `/nome/`:

```ts /nome/
const nome = 'Ana';
console.log(nome);
```

Linguagens suportadas: `ts`, `tsx`, `js`, `jsx`, `bash`, `css`, `json`, `html`, `md`, `mdx`, `sql`, `yaml` e [muitas outras](https://shiki.style/languages).

## Callout

Caixas de destaque para informações importantes. Variantes: `info` (padrão), `tip`, `warning`, `danger`.

<Callout>Mensagem informativa simples, sem título.</Callout>

<Callout variant='info' title='Informação'>
  Use para contexto adicional que complementa o conteúdo principal mas não é
  crítico para o entendimento.
</Callout>

<Callout variant='tip' title='Dica'>
  Use para boas práticas, atalhos ou formas mais eficientes de fazer algo.
</Callout>

<Callout variant='warning' title='Atenção'>
  Use para alertar sobre comportamentos inesperados, deprecações ou armadilhas
  comuns.
</Callout>

<Callout variant='danger' title='Cuidado'>
  Use para avisos críticos — dados que podem ser perdidos, falhas de segurança
  ou erros irreversíveis.
</Callout>

**Sintaxe:**

```mdx
<Callout variant='tip' title='Título opcional'>
  Conteúdo do callout. Suporta `código inline` e **negrito**.
</Callout>
```

| Prop      | Valores                         | Padrão |
| --------- | ------------------------------- | ------ |
| `variant` | `info` `tip` `warning` `danger` | `info` |
| `title`   | `string`                        | —      |

## Mark

Destaca um trecho dentro do texto, como um marca-texto. O componente usa o elemento `<mark>` nativo, então leitores de tela e ferramentas de leitura o reconhecem como texto destacado. O trecho pode conter negrito, itálico, código inline e links.

Esta frase tem um <Mark>trecho destacado</Mark> no meio, e este destaque tem <Mark>**negrito**, `código` e um [link](/blog/mdx-reference)</Mark> dentro.

**Variantes:**

<Mark>default</Mark> <Mark variant='success'>success</Mark>
<Mark variant='info'>info</Mark> <Mark variant='danger'>danger</Mark>

Se o destaque quebrar em mais de uma linha, o arredondamento e o espaçamento se repetem em cada linha.

**Sintaxe:**

```mdx
Um <Mark>trecho destacado</Mark> e um <Mark variant='success'>destaque verde</Mark>.
```

| Prop      | Valores                             | Padrão    |
| --------- | ----------------------------------- | --------- |
| `variant` | `default` `success` `info` `danger` | `default` |

As variantes são só visuais: não use a cor como a única forma de passar um significado. A sintaxe `==texto==` não é suportada, e o GitHub também não a renderiza.

## Tabs

Conteúdo alternado em abas. Ideal para mostrar o mesmo conteúdo em múltiplas variações — gerenciadores de pacotes, linguagens, frameworks.

Cada `Tab` recebe um `label`, e é ele que dá nome à aba: o `Tabs` lê os rótulos dos filhos, sem prop própria para isso. Sem nenhum `Tab`, ou com rótulos repetidos, o build falha. Para mostrar código dentro de uma aba, use um bloco de código normal, com as cercas em linhas próprias.

<Tabs>
  <Tab label='npm'>

    ```bash
    npm install react react-dom
    ```

  </Tab>
  <Tab label='Yarn'>

    ```bash
    yarn add react react-dom
    ```

  </Tab>
  <Tab label='pnpm'>

    ```bash
    pnpm add react react-dom
    ```

  </Tab>
  <Tab label='Bun'>

    ```bash
    bun add react react-dom
    ```

  </Tab>
</Tabs>

Use `defaultValue` para definir qual aba abre por padrão. O valor precisa ser igual ao `label` de uma das abas (padrão: a primeira aba):

```mdx
<Tabs defaultValue='JavaScript'>
  <Tab label='TypeScript'>...</Tab>
  <Tab label='JavaScript'>...</Tab>
</Tabs>
```

**Sintaxe completa:**

```mdx
<Tabs>
  <Tab label='Aba 1'>Conteúdo da aba 1</Tab>
  <Tab label='Aba 2'>Conteúdo da aba 2</Tab>
</Tabs>
```

## Accordion

Conteúdo expansível em seções. Útil para FAQs, glossários e informações complementares.

Por padrão (`type='single'`), apenas um item fica aberto por vez. Com `type='multiple'`, vários itens podem ficar abertos simultaneamente.

<Accordion>
  <AccordionItem title='Quando usar Accordion?'>
    Use quando tiver conteúdo que nem todos os leitores precisarão consultar —
    perguntas frequentes, detalhes avançados, ou explicações alternativas que
    interromperiam o fluxo do texto principal.
  </AccordionItem>

<AccordionItem title='Posso colocar código dentro?'>
  Sim. O `AccordionItem` aceita qualquer conteúdo MDX, incluindo blocos de
  código, listas e outros componentes.
</AccordionItem>

  <AccordionItem title='Qual a diferença entre type single e multiple?'>
    Com `single` (padrão), abrir um item fecha os demais. Com `multiple`, vários
    itens podem estar abertos ao mesmo tempo.
  </AccordionItem>
</Accordion>

**Sintaxe:**

```mdx
<Accordion type='single'>
  <AccordionItem title='Pergunta ou título'>
    Resposta ou conteúdo expandido.
  </AccordionItem>
</Accordion>
```

| Prop   | Valores             | Padrão   |
| ------ | ------------------- | -------- |
| `type` | `single` `multiple` | `single` |

A prop `value` do `AccordionItem` é opcional — por padrão usa o próprio `title` como identificador.

## Imagens

<Callout variant='tip' title='Imagem de capa'>
  A capa do post não usa componente: basta nomear o arquivo `cover` na pasta do
  post. Veja os detalhes em [Como o blog
  funciona](/blog/como-o-blog-funciona#imagem-de-capa).
</Callout>

Todas as imagens usadas no texto seguem as mesmas regras, conferidas no build (veja as [validações](/blog/como-o-blog-funciona#validações-no-build)):

- ficam na pasta `images/` do post e são referenciadas como `./images/nome-do-arquivo.ext`, com o caminho relativo ao `index.mdx`;
- os nomes usam só letras minúsculas, números e hífens (`meu-diagrama.png`): maiúsculas funcionam no macOS e no Windows, mas quebram o build no Linux;
- imagens acima de 1 MB e imagens que nenhum trecho do texto usa geram um aviso;
- imagens remotas (`https://...`) não são suportadas, porque o `next.config.ts` não libera nenhum domínio.

### Imagem inline (Markdown)

Imagens inseridas diretamente no Markdown. O caminho é relativo ao `index.mdx` e o arquivo é importado automaticamente, sem `import` explícito.

![Descrição da imagem](./images/javascript-logo.svg 'Legenda opcional')

**Sintaxe:**

```mdx
![Descrição da imagem](./images/javascript-logo.svg 'Legenda opcional')
```

O texto entre colchetes é o texto alternativo, e o título entre aspas vira a legenda exibida abaixo da imagem.

### Componente Image

Para controlar as propriedades da imagem, use o componente `Image`. Ele exige que a imagem seja **importada**: passar o caminho como texto em `src` gera erro no build.

import MinhaImagem from './images/javascript-logo.svg';

<Image
  src={MinhaImagem}
  alt='Descrição acessível obrigatória'
  caption='Legenda exibida abaixo da imagem. Opcional.'
/>

**Sintaxe:**

```mdx
import MinhaImagem from './images/javascript-logo.svg';

<Image
  src={MinhaImagem}
  alt='Descrição acessível obrigatória'
  caption='Legenda exibida abaixo da imagem. Opcional.'
/>
```

| Prop      | Valores          | Padrão | Descrição                                  |
| --------- | ---------------- | ------ | ------------------------------------------ |
| `src`     | imagem importada | —      | Obrigatória                                |
| `alt`     | `string`         | —      | Texto alternativo, obrigatório             |
| `caption` | `string`         | —      | Legenda exibida abaixo da imagem           |
| `title`   | `string`         | —      | Usado como legenda quando não há `caption` |

### ImageRatio

Imagem com proporção fixa, cortada com `object-cover`. Evita layout shift com imagens de tamanhos variados.

<ImageRatio
  src={MinhaImagem}
  alt='Descrição acessível'
  ratio={16 / 9}
  caption='Legenda opcional.'
/>

**Sintaxe:**

```mdx
<ImageRatio
  src={MinhaImagem}
  alt='Descrição acessível'
  ratio={16 / 9}
  caption='Legenda opcional.'
/>
```

Proporções comuns: `16 / 9` (padrão), `4 / 3`, `1` (quadrado), `21 / 9` (ultrawide).

### Gallery

Grade de imagens quadradas, cortadas com `object-cover`. O número de colunas é definido no `Gallery` e vale para todos os `GalleryImage` dentro dele.

<Gallery columns={3}>
  <GalleryImage src={MinhaImagem} alt='...' caption='Legenda 1' />
  <GalleryImage src={MinhaImagem} alt='...' caption='Legenda 2' />
  <GalleryImage src={MinhaImagem} alt='...' caption='Legenda 3' />
</Gallery>

**Sintaxe:**

```mdx
<Gallery columns={3}>
  <GalleryImage src={MinhaImagem} alt='...' caption='Legenda 1' />
  <GalleryImage src={MinhaImagem} alt='...' caption='Legenda 2' />
  <GalleryImage src={MinhaImagem} alt='...' caption='Legenda 3' />
</Gallery>
```

| Prop      | Componente     | Valores  | Padrão |
| --------- | -------------- | -------- | ------ |
| `columns` | `Gallery`      | `2` `3`  | `3`    |
| `caption` | `GalleryImage` | `string` | —      |

Com `columns={3}`, a grade usa 3 colunas a partir de telas médias e 2 colunas em telas menores.

## YouTube

O `id` é o código na URL do YouTube — em `youtube.com/watch?v=dQw4w9WgXcQ` o id é `dQw4w9WgXcQ`. O player só é carregado quando o leitor clica em reproduzir.

**Sintaxe:**

```mdx
<Youtube
  id='m3DJmtLdqhU'
  title='Título do vídeo'
  caption='Legenda opcional.'
  params='controls=0'
/>
```

| Prop      | Valores  | Padrão | Descrição                                                                                                           |
| --------- | -------- | ------ | ------------------------------------------------------------------------------------------------------------------- |
| `id`      | `string` | —      | Código do vídeo, obrigatório                                                                                        |
| `title`   | `string` | —      | Título do vídeo, acrescentado ao rótulo acessível do botão de reprodução. Sem ele, o rótulo é só "Reproduzir vídeo" |
| `caption` | `string` | —      | Legenda exibida abaixo do player                                                                                    |
| `params`  | `string` | vazio  | Parâmetros do player, como `controls=0`                                                                             |

**Exemplo:**

<Youtube id='m3DJmtLdqhU' />
